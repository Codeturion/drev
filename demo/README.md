# Demo recordings

Tape files for [vhs](https://github.com/charmbracelet/vhs). Each tape produces a deterministic gif that can be regenerated by anyone with the same setup.

| Tape | Purpose | Output |
|------|---------|--------|
| [hero.tape](./hero.tape) | The cross-machine handoff: receiver runs one command, gets the full transcript. | `demo.gif` (repo root, referenced by README) |

## Building

```
# install vhs once
brew install vhs                       # macOS
winget install charmbracelet.vhs       # Windows
go install github.com/charmbracelet/vhs@latest   # any platform with Go

# from the repo root
vhs demo/hero.tape
```

## Recording a fresh hero gif

The hero tape resumes a session named `xos-fix` (an authentic record of fixing a cross-OS bug during drev's own development). To regenerate the gif against a different session:

1. Run `drev list --days 30` to see what you have.
2. Pick one with a short, recognizable name (long names get truncated in the gif).
3. Edit the `Type "drev resume <name>"` line in `hero.tape` to match.
4. Run `vhs demo/hero.tape` from the repo root.

If you want a fresh demo session built from scratch:

1. In any non-sensitive project, run a quick Claude Code session (3-5 messages, contained scope).
2. Say *"save this as <slug>"* — Claude runs `drev share` for you.
3. Confirm with `drev list`.
4. Update `hero.tape` and re-run `vhs demo/hero.tape`.

## Notes

- vhs renders its own terminal, so the gif looks the same on every host. Your local PS1, font, and color scheme don't leak through.
- `Set Shell bash` if you're on Windows and want bash semantics; otherwise PowerShell is the default there.
- Keep the gif under ~1 MB for fast README loads. Default settings here produce ~600-800 kB.
