# T23: autoshare-sweep (internal)

**Phase:** C · **Depends on:** T07, T08, T09, T14
**Architecture refs:** §9.12, §10 (full algorithm)

## Scope

Implement the auto-share sweep called by Claude Code hooks per §10. Internal command — not user-invoked, but works if invoked manually.

### Algorithm (verbatim from §10)

```
1. Acquire ~/.drev/.sweep.lock. If held, exit silently.
2. Read ~/.drev/config.yaml.
3. If auto_share == "manual", release lock and exit.
4. git pull --rebase in repo clone (10s timeout; on timeout, proceed with local).
5. Build set S of already-shared session IDs by walking users/<self>/*/meta.yaml.
6. Walk all ~/.claude/projects/*/*.jsonl. For each:
   a. Skip if mtime within auto_share_idle_threshold_seconds of now.
   b. Skip if session ID in S.
   c. Determine project root from encoded-cwd. Skip if a .drev-disable file exists at that root.
   d. Share with: name = autogenerated, visibility = (private if auto_share=="auto-private" else team).
7. Log results to ~/.drev/logs/autoshare.log.
8. Release lock.
9. Exit silently. Errors go to log only.
```

### Failure escalation (§10)

If 3+ consecutive sweep runs fail, the next interactive `drev` command must print a warning. Track this via a counter in `~/.drev/logs/sweep-failures` (reset on success).

## Acceptance

- Lock contention: second invocation while first is running exits silently
- Manual mode: short-circuits without doing work
- Errors never reach stdout/stderr (verified in tests by capturing streams)
- Failure counter increments on errors, resets on success
- Tests use a fake clock and fake filesystem to simulate idle threshold and walk

## Out of scope

- Bandwidth-aware throttling — out of v0
- Auto-merge of remote changes during sweep — current "10s timeout fallback to local" is enough
- Per-project sweep configuration beyond `.drev-disable` flag file — defer to v0.1
